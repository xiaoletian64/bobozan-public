# 蓝牙双人对战 · 已确认需求与实现设计

更新：2026-09-25。用户明确要求苹果与安卓能通过蓝牙互相对战。本文件是待实现的设计与验收约定，**不是当前 APK 已支持蓝牙的说明**。

## 口令修正范围
只去掉“儿”。口令保持“波、波、攒”“波、波、防”，攻击时为“波、波、波”。“攒”按攒能量的 zǎn 发音，游戏文字仍写“攒”；不因为语音转写成“斩”而更换游戏名称。末拍喊本轮动作，不把“出招”读成额外口令。此前应用户要求后移的锁定时机保留，不因本次去儿化再次调整。

## 必须覆盖的组合
| 组合 | 产品目标 | 当前状态 |
|---|---|---|
| iPhone ↔ Android | 必须互通，优先验收；两边都可发起房间 | 未实现、未真机验证 |
| Android ↔ Android | 必须支持 | 未实现、未真机验证 |
| iPhone ↔ iPhone | 必须支持 | 未实现、未真机验证 |

无需账号、互联网或路由器，两人各持一台手机；首版仅支持前台两人一局。设备需要具备相应 BLE 能力。原有离线对电脑模式保留，不支持/拒绝蓝牙权限时仍可使用。

## 通信路线
采用共同的 Bluetooth Low Energy（BLE）GATT 协议。iOS 通过 Core Bluetooth；Android 通过 BLE 扫描、广播和 GATT client/server API。Godot 保留角色、规则、界面和节拍；分别加原生平台桥接，不为双人另写一套规则。

双方平台均提供 BLE API，因此这是跨系统实现路线；API 存在并不等于本项目跨品牌真机已验证。当前没有可工作的原生桥接插件。

- 广播只携带游戏 service UUID 和协议标识，发现后连接交换房间资料，不把全部游戏状态塞进广播。
- 应用房主与 BLE central/peripheral 角色分开。优先用 iPhone 作为 peripheral、Android 作为 central 验证混合组合；两边谁点“创建”都不应决定谁能获胜或谁先看到出招。
- Android 运行时检查广播支持。若不支持，当扫描/连接端使用；必要时引导对方创建房间。两台都不能广播时明确提示设备组合不支持，不伪装成不断扫描。
- GATT 双向采用写入及通知/指示。按实际协商容量分片，不假设所有手机都有大 MTU；消息带长度、序号和会话标识，限长、限队列、去重、超时重传。
- 连接确认码用于识别是否连到了身边的朋友；不能将短码本身当作完整加密或防中间人保障。

## 玩家流程
首页「附近双人」→ 创建房间 / 加入附近房间 → 展示双方昵称与同一确认码 → 双方准备 → 时钟校准 → 同步三秒倒数 → 连续对战 → 双方确认再来。

在真正接通原生通信前，不在可发布原型里放置会假装搜索、连接成功或对战成功的界面。实现时分别显示：蓝牙关闭、权限未允许、扫描超时、版本不同、连接失败、对方退出、重连中。

Android 12+ 按需申请附近设备的扫描/连接/广播权限，旧版本按平台规定处理扫描权限；iOS 提供蓝牙使用说明。只在玩家进入附近双人时申请，不在单机首页预先申请。不开启后台持续扫描。

## 同步与出招公平
动画由每台手机本地渲染，只交换输入、节拍时刻和规则状态，不传视频或每帧骨骼数据。

1. 建立随机会话 ID，比较协议版本、规则版本/参数摘要；不一致禁止开局。
2. 开始前多次往返测量时钟差和抖动，使用单调时钟。约定未来共同开始时刻，预留同步缓冲。房主不靠“收到数据的瞬间”直接控制对方动画。
3. 玩家暗选仅留本机，到约定锁定时刻固定动作。双方先交换动作承诺：`SHA-256(session_id | round_id | player_id | action | random_nonce)`；nonce 使用足够长的安全随机值和固定序列化格式。
4. 本机已锁定并确认双方承诺后才公开动作和 nonce。验证对方公开值匹配此前承诺；验证能量和动作合法性。这样不能先看到对方明文再换招。断线/拒绝公开仍需独立处理，承诺机制不是完整反作弊系统。
5. 双方都验证成功后，确认一个未来共同释放时刻。实际出招与喊招在该时刻发生；网络模式准备到释放间保留可配置通信余量，不能承诺零延迟。若余量不足则显示“同步中”并共同暂停，不偷偷提前出招，也不把未收到消息当成对方选“防”。
6. 双方用同一 `rules.gd` 独立结算并核对结果摘要。只有一致且双方确认的回合才能进入下一回合或写入成就。

验收应记录实测往返延迟、抖动、两屏出招时差，以及语音相位差。暂定设计目标为多数正常近距离回合两屏可见出招差不超过约 50ms；这是待真机测量和调整的目标，不是 BLE 保证。

两台扬声器同时播口令可能产生回声。默认由房主播放公共节拍口令，双方均显示视觉节拍和本地动作音效；设置中允许选择单端或双端节拍声音，双端需要另测音频延迟。

## 断线、切后台和重连
- 任一端进入后台、蓝牙关闭或心跳超时，两端停止推进新回合，提示等待，不即时判负。
- 明确区分未锁定、已承诺、已公开、已确认结算。重连不得让一方在看过对方动作后重选。
- 未锁定轮可共同取消后重新倒数；锁定后的轮必须恢复同一承诺和动作，只能继续原轮或共同结束整局。
- 只恢复双方确认过的状态快照；不一致则暂停并结束该局，不单方面替换能量或成就。
- 约 15 秒的重连窗口作为初始测试值。超时记“对局中断”，不当作获胜、连胜或新的完整回合。已完成回合的纪念成就可以保留。
- 恢复需要双方确认并三秒倒数。旧会话、旧回合、重复和迟到消息一律不得推进状态。

## 实现分层
- `BleTransport`：扫描、广播、权限、连接、收发、MTU/分片、断开事件；平台桥接层。
- `DuelSession`：房间、准备、时钟同步、承诺/公开、超时、重连、状态摘要；独立于具体平台。
- 输入提供方：电脑模式使用 `Opponent`，双人模式使用经过验证的对方动作。蓝牙延迟不回流进 AI。
- `DuelRules`：继续复用现有纯规则与测试。`BeatClock` 接受会话协商后的未来释放时刻，不能继续仅靠两台独立累计 delta。
- 表现：角色、终结与回合特效继续复用；成就按双方确认的完整回合记录。

## 开发顺序与真机验收
1. 最小原生链路：发现、连接、双向短消息。先 iPhone/Android，交换房主再测；再测两个同平台组合。
2. 原生链路稳定后接 Godot 房间与准备页面；拒绝/撤销权限、蓝牙开关均需可恢复。
3. 接同步时钟、暗选承诺/公开、共同结算与现有动画。
4. 注入延迟、丢包、重复包、乱序、旧会话包、掉线和后台；验证不泄露暗选、不双重结算、不重复解锁。
5. 每种组合至少完成 100 个真实双端回合，测试 20/30 回合成就、再来、双方轮流建房。使用真机进行近距离和较差信号测试；模拟器不能替代无线互通验收。

完成第 1 步只可称“蓝牙通信验证”；第 3 步且通过第 4/5 步后才可称“跨平台蓝牙双人可玩”。iOS 仍需有效原生构建环境和真机签名；当前工程 iOS 工具链问题需先解决。
